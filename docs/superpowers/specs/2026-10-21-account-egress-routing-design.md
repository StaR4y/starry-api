# 账号出站代理与路由策略设计

日期：2026-10-21。状态：设计待确认；尚未开始产品代码实施。

## 1. 目标与已确认范围

账号可以绑定本站管理的代理通道，真实上游请求使用所选节点的出口。支持多个通道、Clash 订阅拉取全部节点，以及账号级并发、消息速率、不同会话容量和冷却设置。

用户已确认：

- 代理内核与 TLS 指纹组件随本站部署，并由本站管理。
- 新增 Claude OAuth / Setup Token 账号，接入同一套路由与限制。
- 用户提供的私密订阅用于实际验证，不写入仓库、测试夹具、文档或日志。

本次 OAuth 支持按“导入 access token / refresh token / 到期时间并自动刷新”实施；Setup Token 支持粘贴或导入长期令牌。本站内 Claude 浏览器登录流程不属于本次拟定范围。现有 Codex 授权增加出口选择，本站执行的初始化、轮询、Token 交换与后续账号请求使用同一通道；用户浏览器中的验证步骤使用浏览器自己的网络。

成功标准是可证明真实请求走指定出口、不同账号并发不串出口、限额跨实例不被突破、绑定节点失效时不静默直连。仅解析或保存代理配置不算完成。

## 2. 现有实现与需要修正的基础

- `proxyUrl` 已存在于实体、导入、DTO 和表单，但没有上游网络代码使用它。
- 一个共享 `upstreamWebClient` 同时服务账号、支付、Turnstile 和资讯等调用，不能直接设置全局账号代理。
- PostgreSQL V8/V9/V10 已负责原子准入、租约、令牌桶、会话容量及作用域冷却，可继续扩展。
- 当前并发不支持“不限”；默认 Anthropic 为 2，OpenAI/Codex/兼容账号为 4，预热还会降低有效上限。
- 当前 Anthropic 只有 API Key 类型，多个分类判断把其他认证方式排除在 Anthropic 路由之外，新增类型必须贯通分类、路由、测试、刷新和失败处理。
- `account_active_sessions` 在每次接受请求时续期，因此已能表达固定滑动窗口内的不同会话数量，不需另建请求事件表。
- 旧 Java 指数冷却和 PostgreSQL 冷却并存，需要统一，否则自定义冷却时间不会准确生效。

## 3. 方案选择

| 方案 | 能力与成本 | 结论 |
| --- | --- | --- |
| Java 直接支持 HTTP CONNECT / SOCKS | 部署简单，但不能运行订阅中的 VLESS/REALITY 等节点，也没有完整 TLS 指纹模拟 | 作为基础传输保留 |
| Java + 随站部署 Mihomo + 长驻 TLS 传输组件 | 代理协议由成熟内核处理，账号规则留在本站；需要管理组件健康、版本和配置 | 采用 |
| 在 Java 中自行实现所有代理协议与 TLS 客户端模拟 | 协议维护、原生兼容和验证成本过高 | 不采用 |

Mihomo 负责节点协议；TLS 组件拟采用基于 `curl_cffi` 的内部长驻服务，负责向最终目标建立 TLS/HTTP2 连接。普通请求使用 Reactor Netty；开启指纹的请求由组件发送，仍穿过同一个所选代理节点。不会把 Mihomo 到代理服务器的 TLS 指纹误当作 Anthropic 看到的目标 TLS 指纹。

## 4. 代理通道与订阅

### 4.1 数据与管理

新增订阅源、代理通道、运行配置版本的数据模型。账号用稳定 `proxyChannelId` 绑定一个通道；多个账号可以绑定同一个通道。

- 手动通道支持 HTTP CONNECT、SOCKS5，以及单个 Clash 节点配置。
- 订阅支持 URL 和 YAML 导入，提取完整配置或 provider 文件中的所有 `proxies`。
- 完整配置中的 HTTP / inline `proxy-providers` 也展开；限制递归、循环、下载数量、内容体积与节点总数。文件 provider 无法访问远端本地文件时明确报错。
- 不执行订阅的 `rules`、监听配置、controller、TUN、脚本、文件路径或其他站级配置。涉及节点依赖的 `dialer-proxy` 必须验证并解析，不可静默丢弃后宣称等价支持。
- 节点按协议能力逐个验证；不支持的节点仍列出原因，不能悄悄漏掉或伪装成 HTTP 节点。
- 展示节点来源、协议、启用/不可用状态、绑定账号数量、最后同步和测试结果；管理接口不回传密码、UUID 等认证材料。
- 节点更新用配置指纹识别原记录；同名不同节点不能覆盖。移除的节点标记失效，保留账号关联；节点身份变化不擅自重绑。
- 支持手动刷新与可选定时刷新。网络错误、格式错误、空订阅或运行配置验证失败保留最后可用版本，并显示失败原因；明确的有效节点删除则标记缺失节点。

### 4.2 运行与路由

每个使用中的 Mihomo 通道分配内部独立 listener，listener 的 `proxy` 固定指向对应节点。请求不通过切换全局代理组来选择出口。

配置生成、校验和激活使用版本号；每个本站实例有本地运行组件，只接受其已激活版本的路由。配置变更后新请求使用新版本，旧连接退出复用，在途请求完成或按明确的取消策略结束。订阅读取与配置发布串行化，避免旧更新覆盖新更新。

节点停用、被订阅移除、运行组件失效或代理认证失败时，该路由不可用。可按现有账号重试策略选择其他可用账号，但不允许将同一已绑定账号降级为直连。删除仍被绑定的通道返回冲突并列出引用。

## 5. 统一账号传输

新增账号感知的传输入口和不可变路由快照。连接池按账号、路由版本和 TLS profile 隔离，并限制缓存总量和连接总量。

以下调用全部接入同一路由：OpenAI / 兼容 API / DeepSeek / Codex / Anthropic / Kiro 推理、账号测试、额度查询、Kiro 模型列表、Token 刷新，以及有出口选择的 Codex OAuth 初始化/轮询/交换。支付、验证码、公开定价等非账号业务继续使用它们自己的客户端。

传输入口保留状态码、重复响应头、字节流、取消与超时语义，避免破坏现有 SSE 解析。代理失败、TLS 组件不可用与上游认证失败分别分类；本地代理 407 不得造成账号 Token 被判失效。

旧 `proxyUrl` 在迁移后以兼容通道或明确的旧版自定义出口方式保留；支持的旧值开始实际生效，不支持的值显示配置错误。不能悄悄清空或忽略。代理解除绑定须支持显式 `null`，PATCH 省略字段表示不修改。

## 6. 账号分类与默认策略

官方判断以认证类型和规范化 Base URL 为准。OpenAI API 官方主机为 `api.openai.com`，Anthropic API 为 `api.anthropic.com`；要求 HTTPS、默认 HTTPS 端口、无 URL 用户信息，按完整主机比较，避免后缀或子串误判。使用默认 Base URL 时先补齐默认值。Codex、Claude OAuth、Setup Token 单独分类。

| 新建账号类别 | 默认代理 | 默认并发 | 附加能力 |
| --- | --- | ---: | --- |
| 官方 OpenAI / Anthropic API Key | 直连，可选通道 | 14 | 可自定义或设为不限 |
| 非官方 API Key / 兼容网关 | 直连，可选通道 | 不限 | 可主动配置上限 |
| Codex 反向代理账号 | 直连，可选通道 | 保留现有默认 4 | 可自定义或设为不限 |
| Kiro 反向代理账号 | 直连，可选通道 | 保留现有默认 2 | 可自定义或设为不限 |
| Claude OAuth / Setup Token | 直连，可选通道 | 2 | TLS profile、消息速率、不同会话窗口、冷却 |

TLS profile、消息速率、不同会话窗口和冷却也对官方 Anthropic API Key、第三方 Anthropic 兼容账号开放，各项均可独立关闭；表中的 OAuth 行强调其新增能力，并非将这些设置限定于该类型。新 API 账号默认不限制会话；新 Claude OAuth / Setup Token 沿用保守的 RPM 20、突发 2、会话上限 4、窗口 600 秒、自动冷却。

拟保留现有账号的显式策略；数据库没有可靠记录可以区分“曾手动设为 4”与“沿用旧默认 4”，因此不猜测覆盖。界面提供“应用此类型的新默认”操作。默认 14 / 不限适用于新建账号和该操作。

`safeConcurrency=0` 明确表示不限，正整数表示上限；响应另给可读的有效策略与分类。不限仍受独立的其他已启用规则约束。新 API 账号默认关闭可选 RPM/突发限制，避免新并发规则被隐藏的旧默认掩盖；既有账号保留原限速配置。在途 Token 保护继续作为高级选项清晰显示。

API 账号不因预热缩小并发；OAuth/Setup Token/Codex/Kiro 保留现有预热机制，并同时显示配置上限、当前有效上限和阶段。“不限”在所有阶段仍为不限。新增、重新启用和冷却到期均遵循同一规则。

## 7. Claude 认证与 TLS profile

- `anthropic-oauth`：导入 access token、refresh token、到期时间和可选 scope；到期前按官方客户端协议刷新。缺 refresh token 的访问令牌到期后要求重新导入，不能伪造续期。
- `anthropic-setup-token`：导入长期 access token，不自动当成 refresh token 使用；失效时要求重新导入。未提供签发/到期时间时显示到期未知，不能从导入时间重新计算有效期；不依靠令牌前缀猜测认证类型。
- API Key 继续使用其 API Key 认证；OAuth/Setup Token 使用 Bearer 认证及对应协议头。不同类型不能互相错误套用认证头。
- OAuth 刷新按账号串行，并通过版本比较原子保存轮换后的令牌，避免多实例刷新相互覆盖；刷新、模型请求和测试都沿用账号出口。刷新 endpoint 使用经过核实的独立官方地址，不把 refresh token 发往任意账号 Base URL；保留原 scope，不主动扩大授权。
- TLS 模拟是独立开关，显示组件实际支持的具体 profile，默认关闭。配置开启而组件不可用时拒绝发送，不静默回退到 Java TLS。
- 不把浏览器 profile 命名为未经验证的“Claude Code 官方指纹”；同一账号使用稳定 profile，不逐请求随机改变。

## 8. 限流、会话和冷却的明确语义

### 8.1 并发与消息速率

并发表示该账号正在处理的模型请求数，不是每秒请求数。取消、完成、失败与租约过期均准确释放计数。限额判断与预留继续在 PostgreSQL 单账号事务锁下执行。

消息限速使用现有 RPM + 突发令牌桶，界面说明它是平均速率与允许的突发数量，不宣称严格滚动一分钟计数。RPM=0 同时关闭 RPM 桶与关联突发桶；RPM>0 时突发容量必须为正整数。达到限制时选其他账号，不阻塞线程等待。

一次成功准入的模型发送尝试扣一次额度，历史 `messages` 数量不影响计数；模型重试和会实际发出模型请求的账号测试也计数。准入后取消或未发送的尝试不退还速率额度，维持保守上限；并发租约仍须释放。仅检查组件健康、不调用模型的探测不计数。维护类 Token 刷新使用独立的账号串行控制，不占模型并发槽，避免刷新死锁。

### 8.2 不同会话窗口

配置 `maxSessions` 和窗口秒数 W，按最近 W 秒被该账号接受的不同会话去重。例如 W=300、上限=2：A、B 已被接受，C 被该账号拒绝并路由到其他账号；A、B 可继续发送且刷新其窗口时间，仍受并发与消息速率限制。

会话标识优先使用明确的会话请求头或请求字段；规范解析 Claude 会话元数据，不把普通用户 ID 自动当作完整会话。按下游 API Key 隔离会话命名空间，仅存 hash。

缺少可靠会话 ID 时，为每个入站请求生成独立合成会话，跨该请求的重试保持一致，只用于配额，不注入上游、不建立粘性绑定。这样既能使用普通客户端，也不能通过省略 ID 绕过上限。

复用 `account_active_sessions`，按当前窗口和 `last_seen_at` 判断，保留至少允许的最大窗口历史；缩短或延长窗口立即按新规则生效。窗口约束应用于实际选中的 Anthropic 账号，不取决于客户端使用哪一种入站兼容协议。

### 8.3 冷却

`cooldownSeconds=0` 表示自动；正数表示暂时容量错误和达到阈值的传输失败所使用的自定义默认冷却。上游明确给出的 Retry-After 作为最低等待时间，取两者较大值。普通并发/会话容量拒绝不会触发额外账号冷却。

账号范围、模型范围和端点范围继续分开，不因为某一模型限流封锁其他模型。永久撤销、管理员禁用与认证/地区隔离保留其既有独立语义。

生产路由移除叠加的旧 Java 指数冷却，由数据库统一决定截止时间。修复“并发失败已触发冷却，但较晚成功清掉截止时间”的竞态；成功不能复活禁用或清除仍有效的冷却，后续失败不能缩短已生效的截止时间。

## 9. 管理界面与接口

- 新增管理员“出站代理”页面：通道、订阅、运行组件状态，节点测试可显示出口 IP、延迟和错误阶段。
- 账号新建和编辑都支持“路由与限制”：后端返回的账号分类、代理通道、并发和适用的附加设置。
- Anthropic OAuth / Setup Token 有明确的凭据表单、到期状态与重新导入入口。
- 创建/更新账号与其策略在同一个事务保存，避免“账号改成功、策略失败”的部分成功。
- 全局路由面板继续负责跨账号选择、亲和、失败换号；账号级规则不散落成重复的全局设置。
- 新增文字补全中英文；保持管理员权限控制、敏感字段脱敏与导入导出兼容。

## 10. 部署、更新与验证

源码 Compose、预构建 Compose、安装脚本、发布脚本与本机启动文档一起更新。组件版本和校验摘要固定，启动时不临时下载未知最新版本。组件端口只在内部网络或回环开放，控制接口鉴权；默认不启用系统代理、TUN 或特权模式。

运行实例支持可选出站网卡设置，默认遵循操作系统路由。已有 VPN/TUN 的开发环境可以只对运行组件指定物理网卡；不把本机 `en0` 固化成服务器默认，也不自动修改宿主机网络设置。

订阅抓取限制 HTTP(S)、目标地址、重定向、超时和解析资源；私密 URL 与节点凭据不记录在普通日志。手动配置本机代理与远程订阅抓取使用不同的地址策略。

数据库新增后续 Flyway 迁移，不改历史迁移；检查数据库权限、备份恢复验证与多实例版本兼容。

验收至少覆盖：

1. 官方/非官方 Base URL 分类、14/不限、新建/编辑/旧配置兼容。
2. 本地 HTTP CONNECT / SOCKS 真实转发与代理认证；同时请求两个不同节点不串出口。
3. Clash 多节点和 provider 展开、重复名、部分不支持、更新失败、节点移除。
4. 用户提供的 VLESS + REALITY 订阅真实连通和出口 IP；真实订阅只作为本机私密测试数据。
5. 所有推理、刷新、测试、额度和模型列表调用均经过所选路由。
6. 绑定节点或 TLS 组件失效时禁止直连/普通 TLS 回退。
7. 真实 PostgreSQL 并发抢占、0=不限、预热、租约释放与过期回收。
8. A/B/C 会话边界、时间到期、缺 ID、跨协议、窗口修改、多实例争抢。
9. RPM/突发与自定义冷却，关闭速率时的合法组合、测试与重试计数、Retry-After 下限，较晚成功与冷却并发竞态。
10. OAuth 刷新轮换竞争、Setup Token 不误刷新、认证头、取消、超时及 TLS 握手验证。
11. 后端测试、前端类型检查/构建/i18n、组件测试及部署配置校验。

## 11. 实施分块

设计确认后按同一任务依次完成：账号传输与代理通道 → 订阅和随站运行组件 → Claude 认证与 TLS 组件 → 原子准入和冷却 → 管理界面与部署 → 集成验证。接口契约固定后，互不重叠的前后端工作可并行。
